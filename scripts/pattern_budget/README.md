# pattern_budget：§4.1.1 结构上界的资源余量探针

connector 契约 §4.1.1 规定 pattern 的长度 ≤ 1024、**分组嵌套深度 ≤ 64**、展开规模 ≤ 4096，并要求「子集内的任何 pattern MUST 被接受并正确匹配」。本探针用 Rust `regex` 引擎的**默认限额**编译子集内最贵的一批 pattern（**转译后**形态：显式字符类/码点区间），证明条款的余量；不达标时应收紧条款，而不是让实现调大限额兜底。

## 运行

```bash
cd scripts/pattern_budget
cargo run --release   # 合法用例全部 OK 退出码 0；任一超出默认限额退出码 1
```

## 基线（2026-10-09，regex 1.13.1，默认 10MB 限额；`cargo run --release`）

| 合法用例（MUST 编译） | 展开规模 | 编译 | 结果 |
| --- | --- | --- | --- |
| `[^0-9A-Za-z_]{255}`（`\W{255}` 的等价简化形态） | 255 | 2ms | OK |
| `[^\n\r] × 1024`（1024 个 `.`，取反类形态） | 1024 | 10ms | OK |
| 显式区间 `.` × 1024（转译输出形态） | 1024 | 5ms | OK |
| 16 码点手写类 × `{255}`（最坏合法形状，与向量同款） | 4080 | 0ms | OK |
| `[aaaa]{1024}`（计数不去重的上界） | 4096 | 0ms | OK |
| `(?:a\|bc){1365}`（选择与嵌套的上界） | 4095 | 1ms | OK |
| `a{4096}`（`{m}` 的上界） | 4096 | 0ms | OK |
| 64 层嵌套 + `a{4096}`（嵌套深度与展开规模同时顶格） | 4096 | 0ms | OK |
| 64 层嵌套每层带量词（最坏嵌套形状） | 1 | 0ms | OK |
| `(?:){4096}`（零尺寸原子计数；分组至少计 1） | 4096 | 0ms | OK |
| 995 码点手写类（无约束） | 995 | 0ms | OK |

越界形状（§4.1.1 判不合法，探针只作对照、不影响退出码）：`(?:.×48){255}`（12240）、`[995 码点类]{255}`（254000）、原生 `\W{255}` 在默认限额下均 ERR；65 层嵌套在当前引擎下**能**编译（纯分组在 250 的解析限额内）——它按深度条款判不合法，探针不据此断言；而「每层带量词」形状在 **125 层**即解析失败，深度条款取 64 正是为此留出两倍余量。

## 约定

- 独立工程：不属于 `sdk/rust` workspace、不进 CI，不牵动 `make check-vectors` 与站点构建（`website/` 不聚合本目录，README 不进 mkdocs nav）；
- `Cargo.lock` 随提交，用于固定基线版本；regex 升级或 Rust 运行器落地时复跑本探针并更新上表；
- 用例与 `vectors/config_schema_patterns.json` 的 `valid_patterns` 对应，规范依据为 connector 契约 §4.1.1；
- 「等价简化形态」（`[^0-9A-Za-z_]`、`[^\n\r]`）与「转译输出形态」（显式码点区间）在表中分别标注——真正交给引擎的是后者，前者作为等价对照一并观测。
