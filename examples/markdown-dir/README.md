# 示例插件：Markdown 目录（markdown-dir）

> **这是示例，不发布，也不是官方 connector**（官方的是 [`connectors/git`](../../connectors/git/)）。
> 它用来示范：**不用 SDK、只靠标准库，任何语言都能写 connector**；同时作为
> [Issue #53](https://github.com/A2C-SMCP/dpe-protocol/issues/53) 的端到端验收夹具，覆盖
> `read_blob` 链路（markdown 引用的本地图片由运行器分块读取并上传）。

把本地目录里的 `.md` 文件映射为 DPE 文档的 **dpe-run 插件**（[connector 契约](../../spec/connector-contract.md) §6）。
插件只产出源内容：不计算 hash（§6.6，hash 由运行器计算）、不接触 DPE remote 与凭证。

## 用法

```bash
uv sync
uv run pytest            # 含真实 dpe-run + 参考服务端的端到端收敛用例

# 实例定义（connector 契约 §4.4）
{
  "definition_version": 1,
  "id": "notes",
  "remote": { "url": "https://dpe.example.com/remotes/x" },
  "uri_prefix": "file://notes/",
  "plugin": { "manifest": "examples/markdown-dir/dpe-connector.json",
              "command": ["dpe-markdown-dir"] },
  "config": { "root": "/srv/notes" }
}
```

| 配置 | 必填 | 说明 |
| --- | --- | --- |
| `root` | 是 | Markdown 文件所在的本地目录（递归，不跟随符号链接） |
| `include_hidden` | 否 | 是否包含以 `.` 开头的目录与文件，缺省 `false` |

## 映射规则

- **文档 = 一个 `.md` 文件**：`file_uri` = 实例前缀 + 相对 `root` 的路径（百分号编码）；
  `file_type` 为 `md`；不写 `title`（身份只放在 `file_uri` 里，改名才是纯粹的 move）。
- **页**：代码块之外单独成行的 `---` 是页边界。
- **元素**（按块，空行分隔）：
  - `#` … `######` 标题 → `Title`，`metadata {"level": n}`；
  - 围栏代码 → `CodeSnippet`，有语言标注时 `metadata {"language": …}`；
  - 列表项 → 每项一个 `ListItem`；
  - 只含一张本地图片的段落 `![alt](path)` → `Image`：`text` 为 alt，`mime_type` 按扩展名查
    固定表（不用系统的 `mimetypes`，避免不同机器得到不同值），`blob` 为句柄
    `{"handle", "size"}`；URL 形式的图片当普通文本，不抓取；
  - 其余段落 → `NarrativeText`（行内图片、链接原样保留为文本）。
- 文本原样进入元素，不渲染、不转义；不写易变字段与位置序号。
- **规则与语言无关**：只按 `\n` 切行（去掉行尾 `\r`，文末的 `\n` 只结束最后一行），「空白」
  只指空格与制表符——不用宿主语言自带的 Unicode 行界 / 空白判定，用别的语言照着实现能得到
  相同的内容与 hash。
- 图片路径相对 md 文件解析，**只读 `root` 之内的普通文件**：越出 `root`（`..`、绝对路径）、
  隐藏路径（`include_hidden` 为 false 时）、符号链接、目录、管道，或路径本身不合法（如含 NUL）
  时都不读，整段按 `NarrativeText` 原样保留——不替 md 作者把 `root` 之外或隐藏的本地文件送上
  remote。打开时不跟随最后一段的符号链接，并核对打开的就是判定过的那个普通文件；偶发的 I/O
  错误（如网络盘 `EIO`）按暂时读不到处理（可重试），不改写成文本。
  图片文件不存在时产出不带 `blob` 与 `mime_type` 的 `Image`（源确实没有字节，契约 §6.6
  合法）；补上之后内容变化、重新投递。

## 图片与 `read_blob`（契约 §6.7）

- 产出文档时把图片字节整体读进内存，作为本轮的**快照**；句柄指向这份字节，轮内任意偏移、
  重复读取都一致，源文件之后再变也不影响本轮。
- 下一轮的轮首 `scan` 或 `shutdown` 时快照清空，旧句柄以 `-32002` 拒绝。
- 每次返回的字节受 `max_message_bytes` 约束（base64 膨胀计入）；运行器按需多次读取。

## 增量、删除与改名（契约 §6.4、§6.5、§6.8）

`capabilities.supports_cursor = true`，结束批给出游标（不透明、自包含，`mdd1.` 开头）。

- 每个文件记一条内容摘要：md 字节的 sha256，后接每张图片的定长记录（类型 + 字节的 sha256，
  或「缺失」「不当作图片」标记）——分开拼接，不同的文件不会得到相同摘要；只用于比较，不是
  DPE hash。
- **每轮都读内容、比摘要**，摘要没变（如只是 touch）就不产出——不制造伪变更。**不靠
  mtime/size 跳过读取**：时间戳有精度、可被保留（`cp -p`），符号链接还有目标，凭它跳过会
  漏掉真实的变化（增量轮 MUST 产出一切变化，§6.8）。示例取正确而不取快。
- **删除**：上一轮有、本轮发现不到 → `delete`。
- **改名**：消失的与新出现的文件内容摘要相同且一一对应 → `move`，同一轮里随后总会产出目标
  的 `document`（内容未变时运行器判为 `unchanged`，代价很小；connector §6.5、§7.2，#178）；
  多对多（如复制出多份再删掉原件）无法确定配对，按 `delete` + 新建处理；改名同时改了内容也按
  `delete` + 新建。
- **delete 成功而游标未推进之后，又新建了同内容的文件**：某轮的 `delete A` 已在 remote 生效，
  但本轮因别的条目出错没有推进游标；之后用户新建了与 A 内容相同的 B，下一轮仍以旧游标配出
  `move A→B`，而 A 已不存在。紧跟的 B 的 `document` 让运行器把 B 建出来、这个 move 按已达成计
  （connector §7.2「move 未达成之后的目标 document」，#178）。
- **发现不完整时不产出 delete / move**（读不了的目录，或读不出的新文件——无权限、不是
  UTF-8 都算：内容问题也会消失，比如文件写到一半、或编码被改回去）：被藏起来的可能正是改名
  目标。若本轮先删了源，本轮又因 error 不推进游标，下一轮以旧游标重判时会配出 move，而源已
  在 remote 上删除——move 永久失败。所以此时消失文件的记录带入新游标，摘要与某个消失文件
  相同的新文件先以 `error` 推迟，并另报一条 error 说明推迟了多少个删除 / 改名；下一轮看得全
  了再判。代价：读不出的新文件一直在，删除就一直推迟（游标本来也被它扣住）。
- **一轮里对每个新文件的判断固定在轮首**：同一轮内不重读，不会出现「轮首读不出、走到它时又
  读出来了」而绕过推迟的情况。
- **新游标不越过未产出的变更**：文件读失败、装不下、分段中途放弃时保留上一轮的记录。
- 游标解释不了（格式、版本、数据源不符，或被篡改）即回退全量轮，`incremental: false`；
  摘要算法变化时游标版本随之递增。

## 单条消息上限（契约 §6.2、§6.5）

批次按编码字节累计；一篇装不下就在页边界分段（`continued`），单页都装不下即整篇
`content_invalid`；结束批放不下游标时单独多发一批。单批里跳过的未变文件数有上限，单个
`scan` 请求的工作量有界。

## 已知限制（示例的取舍）

- **不满足 §8.1-7**（处理长请求期间继续处理 `cancel`）：请求同步处理，`cancel` 到达时对应
  请求已经应答，因此被忽略。每轮都读全部文件，轮首 `scan`（有文件消失时还要预读新文件以配对
  改名）的耗时随目录规模增长；目录很大时运行器的 `scan` 超时可能中止本轮。生产 connector
  须把读循环改成能并发处理控制消息的结构（§6.7）。
- **路径判定的边界**：判定与打开之间，中间目录被换成指向 `root` 之外的符号链接，这个窗口
  没有防（需要逐段以 `dir_fd` + `O_NOFOLLOW` 打开）；`root` 里指向外部文件的**硬链接**是
  普通文件，会被读出——`root` 应只放可以上送 remote 的内容。
- **快照在内存里**：产出的文档引用的图片字节留在内存，直到下一轮开始；超大图片目录请改用
  临时文件。
- **Markdown 只覆盖常见块级结构**：表格、引用块、HTML 块等按普通段落处理。
